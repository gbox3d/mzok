MZOK 동작 원리

퀵터널 주소는 터널을 다시 열 때마다 바뀝니다. MZOK 는 기기마다 지금 주소를 한곳에 모아 두는 포탈입니다. 기기는 바뀐 주소를 MZOK 에 적고, 쓰는 쪽은 기기 ID 로 주소를 찾아 그 터널로 직접 들어갑니다.

먼저 결론

API 는 어디서 도나요?

Cloudflare 에서 돕니다. 요청이 올 때마다 Cloudflare 가 코드를 실행하고, 데이터는 Cloudflare D1 에 있습니다. 이 PC 는 코드를 올릴 때만 씁니다.

MZOK 가 통신을 중계하나요?

아니요. 주소만 알려 줍니다. 실제 데이터는 퀵터널을 통해 기기와 바로 오갑니다.

브라우저에서는 왜 2건이 잡히나요?

다른 사이트로 토큰을 보내기 전에 브라우저가 OPTIONS 로 허락을 먼저 묻기 때문입니다. 허락은 2시간 기억하므로 그동안은 1건씩입니다.

다른 서비스가 API 를 붙이면요?

브라우저 밖(바로터널, 스크립트, 서버, ESP32)은 허락을 묻지 않습니다. 언제나 호출 1번이 1건입니다.

왜 포탈이 필요한가

퀵터널 주소는 프로세스가 다시 뜰 때마다 새로 나옵니다. 이름(기기 ID)을 고정하고 주소만 바꿔 적는 곳이 있어야 합니다.

바로터널이 여는 Cloudflare 퀵터널은 계정 없이 쓰는 임시 터널입니다. cloudflared 가 다시 뜰 때마다 https://<임의 이름>.trycloudflare.com 이 새로 발급되고, 재시작과 재부팅이 모두 주소를 바꿉니다.

주소를 어딘가에 적어 두면 첫 재시작에서 낡습니다. 낡은 주소로 접속이 안 되면 "서버가 죽었다"로 오진하기 쉽습니다. MZOK 는 이 문제를 주소록으로 풉니다. 아래 막대를 움직여 시각마다 어느 주소가 통하는지 보세요.

어디서 도는가

API 와 데이터는 Cloudflare 에 있습니다. 이 PC 에는 떠 있는 서버가 없습니다.

Worker 는 켜 둔 서버가 아닙니다. Cloudflare 가 요청을 받을 때마다 그 데이터센터에서 코드를 실행하고 끝냅니다. 그래서 이 PC 가 꺼져 있어도, pm2 같은 프로세스 관리자가 없어도 API 는 답합니다.

요청 한 번의 여정

Worker 는 요청을 위에서부터 차례로 검사하고, 처음 걸린 곳에서 답을 보내고 끝냅니다.

아래 버튼으로 요청을 골라 보세요. 굵은 선이 그 요청이 지나간 길이고, 검게 칠한 칸이 답이 나온 곳입니다.

저장하는 것

D1 테이블 하나에 기기 하나가 행 하나입니다. 같은 ID 로 PUT 하면 덮어쓰고, 없으면 새로 만듭니다.

덮어쓰기와 새로 만들기는 SQL 한 문장입니다.

INSERT INTO devices (id, url, updated_at) VALUES (?1, ?2, ?3)
ON CONFLICT(id) DO UPDATE SET url = excluded.url, updated_at = excluded.updated_at
RETURNING *

주소는 정규형으로 저장한다

보낸 문자열을 그대로 두지 않고, URL 파서가 해석한 모양으로 바꿔 저장합니다. 검사한 값과 저장한 값이 어긋나지 않게 하려는 것입니다. 쓰는 쪽은 응답의 url 을 쓰면 됩니다.

보낸 값결과
HTTPS://Calm-River-Tall-Oak.trycloudflare.com:443/https://calm-river-tall-oak.trycloudflare.com
https://a.example/x/../y/https://a.example/y
https://a.example/?q=1400 bad_url · 쿼리는 받지 않는다
ftp://files.example400 bad_url · http·https 만

updatedAt 은 마지막으로 PUT 한 시각일 뿐, 주소가 아직 살아 있다는 뜻은 아닙니다. 터널이 DELETE 없이 죽으면 마지막 주소가 그대로 남습니다.

브라우저에서만 요청이 한 건 더 붙는 이유

preflight 는 브라우저가 다른 사이트로 토큰을 보내기 전에 서버에 허락을 묻는 요청입니다. 브라우저에만 있는 규칙입니다.

관리 페이지와 API 는 출처가 다르다

브라우저는 출처(스킴 + 호스트 + 포트)로 사이트를 구분합니다. 경로는 출처에 들어가지 않습니다.

주소출처
https://gbox3d.github.io/mzok/https://gbox3d.github.io
https://mzok.<계정>.workers.dev/v1/deviceshttps://mzok.<계정>.workers.dev

호스트가 다르니 다른 출처입니다. 한 출처의 페이지가 다른 출처로 Authorization 헤더를 실어 보내려 하면, 브라우저는 본 요청 전에 OPTIONS 를 먼저 보냅니다. 서버가 "gbox3d.github.io 는 된다, 2시간 기억해도 된다"고 답해야 본 요청이 나갑니다.

이 규칙은 브라우저가 스스로 지킵니다. 어떤 사이트에서 받은 스크립트가 사용자의 브라우저를 빌려 다른 사이트에 인증 헤더나 PUT·DELETE 를 보내는 일을, 받는 쪽이 허락한 경우로만 좁히려는 장치입니다. curl, Node, 파이썬, ESP32 에는 이 규칙이 없습니다.

직접 눌러 보기

호출하는 쪽을 고르고 호출하기를 눌러 보세요. Worker 가 받은 요청 수와 브라우저가 기억한 허락이 바뀝니다. 1시간 지나기를 두 번 누르면 허락이 만료됩니다.

시뮬레이션 시각 09:00:30
Worker 가 받은 요청2
OPTIONS1
본 요청 GET·PUT1
브라우저가 기억한 허락
  • /v1/devices 1:59:30 남음
  1. 09:00:00GET /v1/devices + 토큰 → 200허락을 받고 보낸다
  2. 09:00:00OPTIONS /v1/devices → 204허락을 2시간 기억한다

허락은 주소(URL)마다 따로 기억합니다. 지금 관리 페이지는 /v1/devices 하나만 부르므로 2시간에 한 번 묻습니다. 나중에 페이지가 다른 주소도 부르게 되면 그 주소는 처음에 한 번 따로 묻습니다.

실측

2026-09-28 · 운영 서버 · 헤드리스 크롬OPTIONSGET
같은 요청 3번, 기본 옵션13
같은 요청 3번, cache: "no-store"33
고친 관리 페이지에서 로그인 + 새로고침 3번14

처음 만든 관리 페이지는 fetch 에 cache: "no-store" 를 넣어서 호출마다 OPTIONS 가 붙었습니다. 크롬은 이 옵션이 있으면 허락 기억도 쓰지 않습니다. 옵션을 빼고 고쳤고, 응답은 서버가 cache-control: no-store 로 보내므로 낡은 목록이 남지 않습니다.

CORS 는 도둑을 막는 문이 아닙니다. 어느 사이트의 페이지가 브라우저에서 이 API 를 쓸 수 있는지 정하는 스위치입니다. 문은 토큰이 지킵니다.

관리 페이지

GitHub 는 페이지 파일만 줍니다. 목록 데이터는 브라우저가 Cloudflare 에서 직접 받습니다.

서버 주소와 토큰은 페이지에도 저장소에도 적혀 있지 않습니다. 쓰는 사람이 입력하고, 그 브라우저에만 남습니다. 다만 요청을 보내는 순간 개발자도구의 네트워크 탭에는 주소가 보입니다. 숨길 수 있는 것은 공개 파일에 적지 않는 데까지입니다.

보안

막지 못하는 것

  • 토큰이 하나라, 토큰을 가진 쪽은 어느 ID 든 덮어쓰고 지울 수 있습니다.
  • 터널은 인증이 아닙니다. 터널 주소를 아는 사람은 그 서비스를 그대로 씁니다. 기기의 서비스는 자기 인증을 가져야 합니다.
  • CORS 는 브라우저만 지킵니다. curl 은 CORS 를 무시하므로 문은 토큰이 지킵니다.

배포와 파일

API 는 wrangler deploy, 관리 페이지는 git push 로 올립니다.

파일 지도

├── apps/worker/
│   ├── src/index.js         API 전부: 라우팅·검사·D1·CORS
│   ├── src/help.js          GET /api/help 본문 (에이전트용, 영어)
│   ├── migrations/          D1 스키마 0001 → 0002
│   ├── test/api.test.mjs    테스트 11개 (로컬 workerd + 로컬 D1)

├── docs/index.html          관리 페이지 (GitHub Pages)
├── docs/how-it-works.html    이 문서 (구조와 동작 원리)
├── readme.md
├── __localfiles/            이 PC 에만 .env(주소·토큰), test.http
└── _forAI/                  이 PC 에만 AI 작업 메모 (실제 장비 주소가 있어 올리지 않음)

토큰을 바꿀 때

  1. 새 값을 __localfiles/.env 의 MZOK_TOKEN 에 적습니다.
  2. apps/worker 에서 npx wrangler secret put MZOK_TOKEN 으로 같은 값을 넣습니다.
  3. 보내는 쪽(바로터널) 설정을 바꿉니다.
  4. 관리 페이지는 로그아웃한 뒤 새 토큰으로 들어갑니다.

자주 헷갈리는 것

이 PC 를 꺼도 되나요?

됩니다. API 는 Cloudflare 에서, 관리 페이지는 GitHub 에서 돕니다. PC 는 코드를 고쳐 올릴 때만 필요합니다.

GitHub Pages 에 두면 API 주소가 숨겨지나요?

페이지 파일과 저장소에는 적혀 있지 않습니다. 하지만 쓰는 사람의 브라우저가 그 주소로 요청하므로, 개발자도구를 열면 보입니다.

저장된 주소로 접속이 안 되면요?

MZOK 는 주소가 살아 있는지 모릅니다. updatedAt 이 오래됐으면 터널이 죽었을 수 있습니다. 쓰는 네트워크의 DNS 가 trycloudflare.com 을 막는 경우도 있습니다(팀 보드 #57: KT DNS).

바로터널은 언제 PUT 하나요?

터널을 열거나 다시 열어 주소가 바뀔 때 보내는 것이 목표입니다. 이 연동은 바로터널 쪽에 붙일 예정이고, MZOK 는 받기만 합니다.

두 기기가 같은 ID 를 쓰면요?

마지막 PUT 이 이깁니다. ID 는 겹치지 않게 정합니다(예: <호스트>-<포트>).

workers.dev 주소가 바뀔 수도 있나요?

Cloudflare 약관상 서브도메인 이름을 바꿀 수 있습니다(미리 통지). 그래서 보내는 쪽은 서버 주소를 설정 한 곳에만 둡니다.

용어

터널링 포탈
기기 ID 로 지금 터널 주소를 찾게 해 주는 고정된 입구. MZOK 의 역할입니다.
퀵터널
cloudflared 가 계정 없이 여는 Cloudflare 임시 터널. 실행할 때마다 *.trycloudflare.com 주소가 새로 나옵니다.
Worker
Cloudflare 가 요청마다 실행하는 JavaScript. 따로 떠 있는 서버 프로세스가 없습니다.
D1
Cloudflare 의 SQLite 데이터베이스. MZOK 는 devices 테이블 하나를 씁니다.
출처 (origin)
스킴 + 호스트 + 포트. 브라우저가 사이트를 구분하는 단위입니다.
CORS
다른 출처의 페이지가 브라우저에서 이 API 를 불러도 되는지 서버가 답하는 규칙.
preflight
브라우저가 본 요청 전에 보내는 OPTIONS 요청.
Access-Control-Max-Age
preflight 허락을 기억할 시간. MZOK 는 7200초로 답하고, 크롬은 최대 2시간까지 기억합니다.
Bearer 토큰
Authorization: Bearer <토큰> 헤더에 싣는 비밀 문자열.
업서트 (upsert)
있으면 덮어쓰고 없으면 새로 만드는 쓰기.
localStorage
출처 단위로 남는 브라우저 저장소. 같은 출처의 모든 페이지가 함께 씁니다.
sessionStorage
탭 하나에만 남는 브라우저 저장소. 탭을 닫으면 지워집니다.
CSP
페이지가 어디에 연결하고 어떤 스크립트를 실행할지 제한하는 규칙.
